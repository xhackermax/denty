# Prisma migrations

Denty production uses versioned Prisma migrations. The baseline must be generated by Prisma itself from `schema.prisma`; do not hand-write or infer the initial SQL.

From the repository root, with dependencies installed and Node.js satisfying the project engine:

```bash
pnpm db:generate
pnpm db:baseline
pnpm db:migrations:check
pnpm db:status
```

`db:baseline` executes `prisma migrate diff --from-empty --to-schema prisma/schema.prisma --script` and stores the result under `0001_baseline/migration.sql`. It refuses to overwrite an existing baseline unless `--force` is explicitly passed to the package-level script. Once a baseline has been deployed anywhere, never rebuild it; create subsequent Prisma migrations instead.

Production deployment applies committed migrations with:

```bash
pnpm db:deploy
```

The baseline SQL is intentionally not checked in until it has been generated with the pinned Prisma CLI (`6.19.0`) and reviewed. This repository's production preflight fails while the baseline is absent.
