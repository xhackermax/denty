# Agenda V12 Operations Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade the V11 modern agenda into a server-backed daily operations system with drag/resize, doctor/cabinet movement, waitlist fill, blocks/holidays, cascaded rescheduling and plan-linked multi-visit scheduling.

**Architecture:** The existing visual status layer remains on appointment cards. All schedule changes go through one availability service and optimistic concurrency. The agenda is not a separate waiting-room module; arrival/in-chair/no-show are appointment states rendered as card layers.

**Spec:** `docs/superpowers/specs/2026-09-16-denty-production-platform-design.md`

## Status colors to preserve

```text
neutral = planned/confirmed
yellow = arrived <= 15 min
red = arrived > 15 min and not in chair
green = in chair
blue = no-show
muted = completed/cancelled
```

Red is an operational alert and remains excluded from decorative menu palettes.

## Acceptance criteria

- V11 state-layer UX preserved.
- Drag/resize is server validated.
- No double-booking through concurrent clients.
- Waitlist suggests but does not silently book.
- Cancellation cascades are proposals until confirmed.
- Doctor/reception visibility rules are enforced by API.
