# Denty Node 24 / Vercel baseline — 2026-09-27

- Runtime target: Node.js 24 LTS.
- `package.json` pins `engines.node` to `24.x`.
- `.nvmrc` and `.node-version` both select major 24.
- Vercel build uses `npm ci` and `node scripts/pipeline/run.mjs vercel-build`.
- Next.js route handlers that require Node use `runtime = "nodejs"`; do not pin per-function minor versions.
- Node 24 is the only supported release line for Denty production in this package.
- Keep the npm lock committed and deploy with `npm ci`.

## Current platform guidance applied

- Next.js 16 uses `proxy.ts` rather than legacy `middleware.ts` for the application proxy boundary.
- Supabase SSR sessions should use cookie-based auth; authorization must be based on verified server identity and RLS, not browser role state.
- Supabase publishable keys may be used client-side; secret/service-role keys are server-only.
- Authenticated/session-refreshing routes must not be cached as shared ISR/CDN responses.
- Vercel should be configured for Node.js 24.x. `engines.node=24.x` remains checked by Denty's release gates.
